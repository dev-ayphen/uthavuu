## Current state: no API exists

Neither product makes a single network call to an application backend.

| Check | `apps/mobile` | `apps/web` |
|---|---|---|
| `fetch(` / `axios` / HTTP client | **0** | **0** |
| API route handlers (`+api.ts`, `route.ts`) | **0** | **0** |
| Base URL / env var for an API | **0** | **0** |
| Auth token / session handling | **0** | **0** |
| HTTP dependency in `package.json` | none | none |

`apps/web` ships **4 runtime dependencies** — `next`, `react`, `react-dom`,
`lucide-react`. There is no database client, no auth library, no HTTP client, no state
library. `apps/mobile` has no networking package either.

## The contract both products imply

The two apps already agree on most shapes. This is the endpoint set their existing UI
requires — derived from the code, not invented.

> ⚠️ **Status: `Not Implemented`.** Nothing below exists. This documents what the built UI
> would need, so the client work already done can be wired without redesign.

### Authentication

| Method | Endpoint | Request | Response | Consumed by |
|---|---|---|---|---|
| `POST` | `/auth/otp/request` | `{ phone }` | `202` | [Login](./mobile/03-login-screen.md) — Continue |
| `POST` | `/auth/otp/verify` | `{ phone, code }` | `{ token, user }` | [OTP](./mobile/04-otp-screen.md) — Verify |
| `POST` | `/auth/admin/login` | `{ email, password }` | httpOnly session cookie + `role` | [Admin login](./webadmin/01-admin-login.md) |
| `POST` | `/auth/logout` | — | `204` | Both logouts |

**Error handling required (none exists today):** invalid phone `400`, wrong code `400` with
attempts remaining, expired code `410`, rate limit `429`, wrong admin credentials `401`.

## Data model mismatches to resolve first

These will cause silent data corruption if the two clients are wired to one API as-is.

| Field | Mobile | Admin | Fix |
|---|---|---|---|
| `profession` | id — `'software_engineer'` | label — `'Software Engineer'` | Store the **id**; ship `PROFESSIONS` in `libs/shared` |
| Location | one free-text `city` | `city` **+** `district` | Adopt both; district drives admin analytics and broadcast targeting |
| Flag reason | 7 values | 5 values | Agree one enum |
| Support ticket type | 6 | 4 | Agree one enum |
| Categories | 8 (9 in the report wizard) | 8 | Single source; move expiry rules server-side |
| User status | *(no concept)* | Active / Suspended / **Blocked** | Mobile must handle a blocked user |
| Ticket id | `Math.random()` client-side | server-shaped | Server issues ids |
| Version | `1.0.4` hardcoded / `1.0.0` in `app.json` | `2.1.0` from settings | One source |

`libs/shared/src/index.ts` already declares `HelpRequest`, `UserProfile` and `ImpactStory`
interfaces — and **nothing imports it**. It is the natural home for the shared enums and
types above.

## Security requirements for the first integration

| # | Requirement | Current state |
|---|---|---|
| 1 | Move admin credentials server-side | Hardcoded in a client component and printed on the page |
| 2 | Issue an httpOnly session cookie | No session of any kind |
| 3 | Derive role from the session, not the URL | `?role=super` is self-grantable |
| 4 | Guard `/admin/*` in middleware | No guard — the console is public |
| 5 | Enforce the 6-flag permission matrix server-side | Stored, displayed, never read |
| 6 | Write an audit entry per mutation | Never written |
| 7 | Rate-limit OTP request and verify | No endpoint yet |
| 8 | Validate every field server-side | Mobile validates 4 places in 34 inputs |

No secrets, keys or tokens appear anywhere in this documentation. The only credentials in
the codebase are the two demo admin passwords, which are already printed in the product's
own UI — see [01 — Admin Login §4](./webadmin/01-admin-login.md#4--security-assessment).
